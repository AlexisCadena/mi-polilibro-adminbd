Glosario

Explora los términos clave, acrónimos y definiciones relacionadas con la administración de bases de datos.

A Términos con A

ACID:
Acrónimo de Atomicidad, Consistencia, Aislamiento y Durabilidad: las cuatro propiedades que el gestor de transacciones garantiza a toda transacción para que los datos permanezcan correctos incluso ante fallas o accesos simultáneos.

Administrador de Base de Datos (DBA):
Profesional responsable de la instalación, configuración, seguridad, monitoreo y mantenimiento de los sistemas de bases de datos de una organización.

Analizador (Parser):
Componente del procesador de consultas que revisa la sintaxis de la instrucción SQL recibida antes de que el optimizador elija cómo ejecutarla.

Atributo:
Cada una de las propiedades o características que definen a una entidad en el modelo relacional (corresponde a las columnas de una tabla).

Autenticación:
Proceso mediante el cual el SMBDR verifica la identidad de un usuario (por ejemplo, con usuario y contraseña) antes de permitirle conectarse.

Autorización:
Proceso mediante el cual el SMBDR determina qué acciones puede realizar un usuario ya autenticado y sobre qué objetos, con base en los privilegios que se le hayan otorgado.

B Términos con B

Backup (Respaldo):
Copia de seguridad de los datos que permite restaurar la información en caso de pérdida, corrupción o falla del sistema. Puede ser en frío (base de datos apagada) o en caliente (en ejecución).

Bitácora (Archivo bitácora / Transaction Log):
Registro donde el SMBDR anota cada cambio antes de aplicarlo a los datos, usado para la recuperación ante fallas. Recibe un nombre distinto según el motor: Transaction Log (.ldf) en SQL Server, Binary Log (binlog) en MySQL/MariaDB, Write-Ahead Log (WAL) en PostgreSQL y Redo Log en Oracle.

Bloqueo (Locking):
Mecanismo de control de concurrencia mediante el cual una transacción reserva un dato antes de leerlo o modificarlo, para que otras transacciones no interfieran; puede ser compartido (S, para lectura) o exclusivo (X, para escritura).

C Términos con C

Catálogo del sistema (Diccionario de datos):
Conjunto de tablas internas del SMBDR donde se guardan los metadatos: nombres de tablas, columnas, tipos de dato, usuarios y permisos existentes.

CHECK:
Restricción de integridad que exige que el valor de una columna cumpla una condición lógica (por ejemplo, salario > 0) antes de aceptarse.

Clave candidata:
Cualquier atributo o conjunto de atributos capaz de identificar de forma única cada fila de una tabla; de entre las claves candidatas se elige la clave primaria.

Clave foránea (Foreign Key):
Atributo que referencia la clave primaria de otra tabla, estableciendo un vínculo entre ambas y garantizando la integridad referencial.

Clave primaria (Primary Key):
Atributo, o conjunto de atributos, que identifica de forma única cada fila (tupla) de una tabla.

Commit:
Instrucción del Lenguaje de Control de Transacciones (TCL) que guarda de forma permanente todos los cambios realizados durante la transacción actual.

Concurrencia:
Capacidad de un Sistema Gestor de Bases de Datos para permitir que múltiples usuarios accedan y modifiquen los datos simultáneamente sin perder la integridad de la información.

Consulta (Query):
Instrucción SQL, normalmente basada en SELECT, con la que se solicita al SMBDR un subconjunto de información.

Cursor:
Puntero que permite recorrer, fila por fila, el resultado de una consulta dentro de un bloque de código procedural (por ejemplo, dentro de un procedimiento almacenado).

D Términos con D

DCL (Data Control Language):
Subconjunto de SQL utilizado para controlar el acceso a los datos, otorgando o revocando privilegios (Ej. GRANT, REVOKE).

DDL (Data Definition Language):
Subconjunto de SQL utilizado para definir o modificar la estructura de los objetos en la base de datos (Ej. CREATE, ALTER, DROP).

Deadlock (Interbloqueo):
Situación en la que dos o más transacciones se bloquean mutuamente esperando un recurso que la otra tiene, formando un ciclo que el SMBDR debe detectar y resolver (normalmente haciendo ROLLBACK a una de ellas).

Disparador (Trigger):
Bloque de código que se ejecuta automáticamente cuando ocurre un evento determinado (INSERT, UPDATE o DELETE) sobre una tabla, sin que ningún programa lo invoque explícitamente.

DML (Data Manipulation Language):
Subconjunto de SQL utilizado para gestionar los datos dentro de las estructuras (Ej. SELECT, INSERT, UPDATE, DELETE).

Dominio:
Conjunto de valores válidos que puede tomar un atributo (por ejemplo, solo enteros positivos para una columna "edad").

E Términos con E

Entidad:
Objeto o concepto del mundo real sobre el que se necesita guardar información (por ejemplo, un alumno o un producto); al implementarse en la base de datos se convierte en una tabla.

Extensión (Extent):
Conjunto de bloques o páginas contiguas que el SMBDR reserva como unidad de crecimiento dentro de un archivo de datos.

F Términos con F

FOREIGN KEY:
Ver Clave foránea (letra C).

Función (Function):
Objeto programable que siempre devuelve un valor y puede invocarse dentro de una expresión SQL, como en SELECT funcion(columna).

G Términos con G

Grafo de espera (Wait-for graph):
Representación que usa el SMBDR para detectar interbloqueos: si se forma un ciclo entre las transacciones que esperan recursos entre sí, existe un deadlock.

GRANT:
Instrucción DCL que otorga uno o más privilegios a un usuario o rol sobre un objeto de la base de datos.

I Términos con I

Índice (Index):
Estructura auxiliar (comúnmente un árbol B+) que acelera la búsqueda de filas sin tener que revisar toda la tabla.

Integridad:
Conjunto de reglas que garantizan que los datos almacenados sean correctos y consistentes; se distingue de la seguridad, que regula quién puede acceder a esos datos.

Integridad referencial:
Regla que garantiza que el valor de una clave foránea siempre exista en la tabla que referencia.

Isolation Level:
Ver Nivel de aislamiento (letra N).

J Términos con J

JOIN:
Operación SQL que combina filas de dos o más tablas relacionadas mediante una condición de coincidencia; sus variantes principales son INNER JOIN, LEFT JOIN, RIGHT JOIN y FULL JOIN.

L Términos con L

Lectura fantasma (Phantom read):
Anomalía de concurrencia en la que una consulta repetida dentro de la misma transacción devuelve filas nuevas que otra transacción insertó de por medio.

Lectura no repetible (Non-repeatable read):
Anomalía en la que, al leer el mismo dato dos veces dentro de la misma transacción, se obtienen valores distintos porque otra transacción lo modificó de por medio.

Lectura sucia (Dirty read):
Anomalía en la que una transacción lee datos que otra transacción modificó pero todavía no ha confirmado con COMMIT.

Locking:
Ver Bloqueo (letra B).

M Términos con M

Metadatos:
Literalmente "datos sobre los datos": información que describe la estructura de la base de datos (nombres de tablas, columnas, tipos, restricciones, permisos), almacenada en el catálogo del sistema.

Modelo relacional:
Forma de organizar la información propuesta por Edgar F. Codd en 1970, que representa los datos como un conjunto de tablas (relaciones) basadas en la teoría de conjuntos y la lógica de predicados.

Módulo (del SMBDR):
Componente instalable por separado que agrega una función administrativa específica al motor, por ejemplo un agente de tareas programadas o un módulo de reportes.

N Términos con N

Nivel de aislamiento (Isolation Level):
Configuración que determina qué tan protegida está una transacción de los efectos de las demás. Los niveles estándar, de menor a mayor protección (y menor a mayor costo en rendimiento), son READ UNCOMMITTED, READ COMMITTED, REPEATABLE READ y SERIALIZABLE.

Normalización:
Proceso de organizar las tablas de una base de datos para reducir la redundancia y evitar anomalías, aplicando un conjunto progresivo de reglas llamadas formas normales (1FN, 2FN, 3FN, etc.).

O Términos con O

Optimizador de consultas:
Componente del SMBDR que, a partir de una instrucción SQL ya analizada, elige el plan de ejecución más eficiente para obtener el resultado solicitado.

P Términos con P

Página / Bloque:
Unidad más pequeña de almacenamiento físico que administra el SMBDR; varias páginas forman una extensión.

Parser:
Ver Analizador (letra A).

Pérdida de actualización (Lost update):
Anomalía de concurrencia en la que dos transacciones modifican el mismo dato y una de ellas sobrescribe, sin darse cuenta, el cambio que había hecho la otra.

Privilegio:
Permiso específico otorgado a un usuario o rol para realizar una acción (por ejemplo, SELECT, INSERT o DROP) sobre uno o varios objetos de la base de datos.

Procedimiento almacenado (Stored Procedure):
Bloque de código SQL/procedural que se guarda en el servidor y se ejecuta explícitamente mediante CALL o EXEC, opcionalmente recibiendo parámetros.

Q Términos con Q

Query:
Ver Consulta (letra C).

R Términos con R

Recuperación (Recovery):
Proceso de usar los respaldos, junto con el registro de transacciones (bitácora), para devolver una base de datos a un estado consistente después de una falla.

Redundancia:
Repetición innecesaria de la misma información en distintos lugares de la base de datos; un buen diseño relacional busca minimizarla.

Regla de Codd:
Cada una de las trece condiciones (numeradas de 0 a 12) que Edgar F. Codd definió para que un sistema pueda considerarse verdaderamente relacional.

Relación:
Nombre formal, en el modelo relacional, de lo que comúnmente se conoce como tabla.

Replicación:
Mecanismo que mantiene una copia sincronizada de la base de datos en otro servidor, normalmente bajo un esquema maestro-esclavo (master-slave).

Restricción (Constraint):
Regla definida sobre una tabla (PRIMARY KEY, FOREIGN KEY, NOT NULL, UNIQUE, CHECK, DEFAULT) que el SMBDR aplica automáticamente para garantizar la integridad de los datos.

REVOKE:
Instrucción DCL que retira uno o más privilegios previamente otorgados a un usuario o rol.

Rol (Role):
Conjunto de privilegios agrupados bajo un nombre, que puede asignarse a uno o varios usuarios para simplificar la administración de permisos.

Rollback:
Instrucción TCL que deshace todos los cambios realizados durante la transacción actual, regresando los datos al estado previo.

S Términos con S

Savepoint:
Punto de control intermedio dentro de una transacción, al cual se puede regresar con un ROLLBACK parcial sin deshacer toda la transacción.

Seguridad:
Conjunto de mecanismos (autenticación y autorización) que regulan quién puede acceder al SMBDR y qué puede hacer, a diferencia de la integridad, que regula que los datos sean correctos.

SMBDR:
Sistema Manejador de Bases de Datos Relacionales. Software que permite la creación, gestión y administración de bases de datos basadas en el modelo relacional.

SQL (Structured Query Language):
Lenguaje de programación estándar e interactivo para la obtención de información y administración de bases de datos relacionales.

Subconsulta (Subquery):
Consulta SQL anidada dentro de otra consulta, usada normalmente dentro de una cláusula WHERE, FROM o SELECT.

T Términos con T

Tablespace / Filegroup:
Unidad lógica de almacenamiento que agrupa uno o varios archivos físicos donde el SMBDR guarda los datos.

TCL (Transaction Control Language):
Subconjunto de SQL que controla el resultado de una transacción (Ej. COMMIT, ROLLBACK, SAVEPOINT).

Transacción:
Conjunto de una o más operaciones SQL que se ejecutan como una sola unidad indivisible: o se confirman todas (COMMIT) o se deshacen todas (ROLLBACK).

Trigger:
Ver Disparador (letra D).

Tupla:
Nombre formal, en el modelo relacional, de lo que comúnmente se conoce como fila o registro.

U Términos con U

UNIQUE:
Restricción de integridad que impide que se repitan valores en una columna.

Usuario vs. Login:
En algunos motores (como SQL Server) se distingue entre el login (la cuenta a nivel de todo el servidor) y el usuario (su representación dentro de una base de datos específica).

Utilería de mantenimiento:
Programa o comando que automatiza tareas rutinarias de mantenimiento, como verificar la integridad física de los archivos o reorganizar índices fragmentados (por ejemplo, DBCC CHECKDB, VACUUM o OPTIMIZE TABLE).

V Términos con V

Vista (View):
Consulta almacenada que se comporta como una tabla virtual, sin duplicar físicamente los datos.
